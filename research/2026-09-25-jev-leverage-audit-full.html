Rationale

Back to top

Yes. About 60 of the ~102 regex sites in draft-view.ts still make semantic decisions, and Jev can take most of them over. Batch closed-set enum signals and per-field “stated?” nouls into the existing classify call. Use Jev’s candidate-pick and date-part patterns for values. Keep math, dates, and formatting in code. Shapeshift is not a precedent for this: its “offline” mode is a regex classifier, and it keeps all field extraction deterministic.

Research frame

Back to top

F2 · Batch more questions into one Jev call

Jev evaluates every question in parallel and in isolation, and “adding questions barely changes the response time” (Introduction). In the parallel-questions cookbook, one 13-question call was 10× faster than separate calls (docs index). Add all enum signals and per-card “stated?” nouls to the jev.py classify call; this is speculative fan-out (Speculative fan-out). The three serial calls in expand.py (components, modes, ingredients) can also merge into one or two.

F3 · A value pattern with no hallucination: candidate pick

An over-finding regex or parser proposes candidate spans. A Jev Choice with a none option picks the one the question asks for, and code copies it verbatim (Pre-parsed value extraction). This keeps regex, but moves it from deciding to proposing candidates. It suits attendees, place, merchant, amount, and store.

F4 · Dates as Jev part-choices, calendar math in code

Seven Choice questions (mode, month, day, year, day_anchor, weekday, week_offset) go in one call. Code resolves them, and a result below 0.60 confidence goes to review (Date extraction cookbook). Jev 1.13 is unreliable at date comparison, math, counting, and generation (Jev 1.13 jaggedness).

F5 · Use confidence as a second axis

Choice and Score return confidence (Confidence-gated routing). Today only switching.py uses it. Proposed uses: a low-confidence field becomes a dashed chip instead of a filled one; Enter commits only when it is confident; ambiguous input shows a clarification card. This is the approve / block / review pattern from the OpenRouter Jev gate and the clarification-vs-comparison control from the CopilotKit Jev generative UI cookbook.

F6 · Shapeshift: what to copy and what not to

“Works offline” means a hand-written keyword/regex classifier that returns fabricated distributions, not a local Jev model (anishfn/shapeshift:src/lib/jev/mock.ts:L21-L156). Online mode makes one systemOne call with 14 static questions (8 choice, 4 noul, 2 score) over {text} (src/lib/jev/questions.ts:L1-L105). Dates come from chrono-node, and people, places, lists, timers, and calc come from regex (src/lib/parse/*.ts). Worth copying: per-card signal registry metadata, the readiness score used as continuous emphasis, and the debug distributions. Our app already goes past shapeshift on field semantics.

F7 · Awesome Jev directory

The directory is mostly SDKs. Relevant patterns: jod / zod-jev (semantic schema validation, a fit for validating chip edits), jev-harness-router (a ~350 ms per-turn route with a regex fallback on deadline), qualm (an uncertain answer is a separate type), and asynq-io/system-one (claims “hosted and local”, not verified). None of these shows local Jev inference.

Evidence test

Back to top

Supports the recommendation

  • First-party docs recommend exactly this split: Jev decides, code computes (jaggedness, date cookbook).
  • Batching adds little latency (introduction, parallel cookbook).
  • The function-calling cookbook maps per-argument Choice plus a “stated?” noul in one 54-question request, which matches our 19-card field model.
  • The CopilotKit and OpenRouter cookbooks both use Jev to choose a UI or action, with an LLM fallback.

Challenges the recommendation

  • Shapeshift keeps extraction deterministic. It shows no failed Jev extraction experiment, and it also shows no success.
  • Jev reads literally and cannot generate, segment, or count, so Luna is still needed for titles, list normalization, and grocery expansion.
  • No accuracy data exists yet for candidate-pick on our phrases.
  • A larger classify payload has not been measured in our app; we saw 3–4 s at 13 concurrent requests.
